# 顶会、顶刊与 CCFDDL：如何选择投稿目标

> 最后核验：2026-07-21  
> 易变化内容：CCF 推荐目录、会议日期、截稿时间、投稿轮次和论文类型。所有时间必须回到会议或期刊官网确认。

“顶会”和“顶刊”不是严格统一的官方术语。它们通常表示某个研究子领域中长期受到研究共同体认可、审稿标准较高、成果传播范围较广的会议或期刊。

一个 venue 是否适合你的论文，不能只看排名。研究主题匹配、证据成熟度、论文类型和时间安排通常更重要。

## 先理解常见发表形式

| 形式 | 常见特点 | 需要注意 |
| --- | --- | --- |
| Conference full/regular paper | 有明确截稿时间、集中审稿、录用后在会议报告 | 页数紧、周期固定、不同领域认可度差异很大 |
| Journal article | 滚动或分期投稿、篇幅通常更长、可能多轮修改 | 审稿时间可能较长，适合完整系统或扩展研究 |
| Workshop paper | 聚焦新兴问题、交流早期结果 | 通常不能与主会 full paper 等同 |
| Short paper | 篇幅较短，贡献类型和评价标准可能不同 | 不同会议对 short paper 的定位不同 |
| Findings / Companion | 主会相关出版渠道，但录用标准和展示方式可能不同 | 不能自动视为主会 full paper |
| Demo / System paper | 强调系统展示、实现或应用 | 需要检查是否要求可运行系统和现场演示 |
| Dataset / Benchmark paper | 强调数据、评测和资源价值 | 重点是质量、许可、覆盖范围和长期可用性 |

CCF 推荐目录当前明确说明，其会议论文通常指 full paper 或 regular paper；short paper、demo、technical brief、summary、findings 和 workshop 等形式不能简单按同一目录类别计算。

## 什么是“顶会”

计算机领域特别重视会议。一些子领域的主要成果首先发表于同行评审会议，会议论文可能是完整、正式和可归档的研究成果。

通常被称为顶会的会议会同时具备其中多项：

- 在目标子领域有长期稳定的学术共同体；
- 论文经过严格同行评审；
- 发表的是完整研究，而不只是摘要；
- 具有稳定的程序委员会、出版和学术规范；
- 重要新问题、方法和数据经常首先在此出现；
- 研究者会持续跟踪该会议，而不是只关注一次排名；
- 论文与目标读者高度匹配。

但以下判断不可靠：

- “录用率低，所以一定是顶会”；
- “CCF A，所以所有方向都必须投”；
- “某篇论文引用高，所以 venue 一定更好”；
- “会议名气大，所以不匹配主题也值得投”；
- “主会、workshop、findings、short paper 完全等价”。

## 什么是“顶刊”

顶刊通常指某一子领域中长期可信、编辑和审稿机制成熟、对完整研究贡献要求较高的期刊。

常见特征包括：

- 主题范围清晰，目标读者稳定；
- 编辑委员会和同行评审机制成熟；
- 要求方法、实验、理论或系统证据完整；
- 能容纳比会议论文更充分的分析、证明、实验和限制讨论；
- 对重复内容、扩展稿和数据伦理有明确要求；
- 在该子领域被持续阅读和引用。

“顶刊”不等于只看影响因子。影响因子会受到领域规模、文章类型和统计窗口影响，不能直接判断单篇论文质量。

## 顶会与顶刊的常见差别

| 维度 | 会议 | 期刊 |
| --- | --- | --- |
| 投稿时间 | 固定 deadline 或轮次 | 常见滚动投稿，也可能有专刊截止时间 |
| 审稿节奏 | 集中、相对固定 | 可能多轮修改，周期差异较大 |
| 篇幅 | 通常更紧 | 通常允许更完整展开 |
| 展示方式 | 现场或线上报告、poster | 以正式文章传播为主 |
| 适合内容 | 及时、完整但篇幅受限的新结果 | 更系统的研究、扩展实验、理论或长期项目 |
| 风险 | 错过 deadline 需等下一轮 | 审稿时间可能不可预测 |

不同子领域差异很大。不要把其他学科“期刊一定高于会议”的规则直接套到计算机领域，也不要把所有计算机子领域都当作会议优先。

## CCF A/B/C 是什么

中国计算机学会发布《CCF 推荐国际学术会议和期刊目录》，按研究领域列出 A、B、C 三类推荐会议和期刊。

正确用法：

- 快速了解一个领域有哪些长期存在的主要 venue；
- 检查会议和期刊所属方向；
- 作为课题组讨论投稿目标的一个参考；
- 与导师、同门和目标社区的实际经验一起使用。

错误用法：

- 把 CCF 类别当作单篇论文质量分数；
- 认为 CCF A 的所有论文都比 B/C 更强；
- 忽略论文类型、主题匹配和真实贡献；
- 用目录代替阅读该 venue 最近论文；
- 认为目录外的新兴 venue 一定没有价值。

CCF 官方明确说明，该目录是推荐建议，不建议任何单位将其简单作为学术评价依据；会议或期刊的整体影响力也不能直接代表其中每篇论文的影响力。

官方入口：

- [CCF 推荐国际学术会议和期刊目录](https://www.ccf.org.cn/Academic_Evaluation/By_category/)

## CCFDDL 是什么

[CCFDDL](https://ccfddl.com/) 是计算机会议 deadline 聚合与倒计时网站，可按方向、CCF 类别和会议名称查看可能的截稿时间。

它适合：

- 快速发现未来几个月可能投稿的会议；
- 比较多个会议的 abstract 和 full-paper 时间；
- 建立个人投稿日历；
- 订阅截止时间提醒。

它不适合充当最终依据。CCFDDL 明确说明数据由人工收集，仅供参考。会议可能临时修改 deadline、时区、轮次、论文类型或投稿入口。

## 使用 CCFDDL 的正确流程

```text
按研究方向筛选候选会议
→ 查看会议全称、年份和论文类型
→ 打开会议官方 CFP
→ 核对 abstract / submission / supplementary 时间
→ 核对 AoE、UTC 和本地时区
→ 核对模板、页数、匿名和双盲要求
→ 写入自己的日历并设置提前提醒
```

### 必须核对的时间

- abstract registration；
- full-paper submission；
- supplementary material；
- author response 或 rebuttal；
- notification；
- camera-ready；
- conference dates。

不要只记录一个“DDL”。有些会议要求先注册摘要，错过后即使正文尚未截止也无法投稿。

### 时区陷阱

常见时间标记包括：

- **AoE**：Anywhere on Earth，通常对应 UTC-12；
- **UTC**：协调世界时；
- 会议所在地时间；
- 投稿系统显示的账户本地时间。

在日历中同时记录：

```text
官方时区：
换算后的本地时间：
来源页面：
最后核验日期：
```

## 如何判断一个 venue 是否适合论文

不要先问“它是不是顶会”，先问：

### 1. Scope 是否匹配

- 最近两年是否持续发表与你问题接近的论文？
- 你的 closest prior work 是否来自该 venue？
- 论文更偏方法、系统、理论、应用还是数据？
- 审稿人是否可能理解你的评价标准？

### 2. 证据是否成熟

- 核心假设是否已经得到可信验证？
- baseline、公平比较、消融和 failure analysis 是否完整？
- 论文能否在页数内清楚表达？
- 负结果是否削弱主要主张？

### 3. 时间是否现实

- 距离 deadline 还有多少完整实验周期？
- 是否有时间做多随机种子和内部审稿？
- supplementary 和匿名材料是否来得及整理？
- 是否因为赶 deadline 而准备提交不稳定结果？

### 4. 投稿政策是否允许

- 是否允许 arXiv 或预印本；
- 是否双盲；
- 是否有并行投稿限制；
- 是否需要伦理声明、数据声明或 artifact；
- 是否允许使用生成式 AI，需不需要披露；
- 扩展期刊稿与已有会议稿需要新增多少内容。

## 新人常见误区

### 只看 CCF 类别

CCF 分类可以用于导航，但不能代替 scope 和论文质量判断。

### 只追最近的 deadline

最近的 deadline 往往会诱导仓促实验。应先判断论文是否成熟，再选择时间窗口。

### 同时准备多个完全不同模板

在研究主张尚未稳定时频繁换 venue，会造成无效改写。先形成一份内部完整稿，再适配具体模板。

### 把 workshop 当作失败

Workshop 可以用于讨论早期问题、建立反馈和认识研究共同体，但必须清楚标注论文形式，不能把它包装成主会 full paper。

### 把“顶会拒稿”当作研究否定

拒稿可能来自贡献不足、实验缺失、表达问题、scope 不匹配或审稿随机性。需要逐条分析证据，而不是只用 venue 名称评价项目。

## 最终检查

- [ ] 知道候选 venue 的完整名称和研究范围
- [ ] 阅读了最近两年的相关论文，而不只看排名
- [ ] 区分 full paper、short、findings、workshop 和 demo
- [ ] CCF 类别只作为参考，不作为论文质量结论
- [ ] CCFDDL 时间已回到官方 CFP 核验
- [ ] abstract、正文和 supplementary deadline 均已记录
- [ ] 时区已经换算并设置提前提醒
- [ ] 投稿政策、匿名、伦理和并行投稿要求已检查
- [ ] 选择 venue 的理由是主题和证据匹配，而不是只追名称
