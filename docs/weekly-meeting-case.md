# 第一次组会：从流水账到研究判断

组会的目标不是证明你很忙，而是让导师和同门快速判断：问题是什么、证据是什么、当前结论是否可信、下一步需要什么决策。

## 一个常见的失败汇报

```text
这周读了 12 篇论文；
跑了几个实验；
效果不太好；
下周准备继续调参。
```

这类汇报缺少问题、证据和判断。听众无法判断你遇到的是实现错误、实验设计错误，还是核心假设错误。

## 推荐结构

```text
1. 本周要减少哪个不确定性？
2. 做了什么最小验证？
3. 得到了什么关键证据？
4. 证据支持或反对什么解释？
5. 目前有哪些未排除因素？
6. 下一步继续、修正还是停止？
7. 需要导师决定什么？
```

## 完整案例

假设研究问题是：

> 冲突证据出现时，RAG 模型是否更容易选择重复次数较多的证据，而不是语义相关性更高的证据？

### 第 1 页：先给结论

```text
本周结论：在控制文档长度和检索分数后，
证据重复次数仍显著影响模型回答；
但当前实验无法排除位置偏置。
```

不要先讲十分钟背景。听众应当首先知道你的当前判断。

### 第 2 页：展示最小实验

说明：

- 自变量：正确与错误证据的重复次数；
- 控制变量：文档长度、相关性分数、出现位置；
- 因变量：最终答案选择；
- 模型与数据；
- 随机种子和样本量。

只保留理解结论所需的设置。

### 第 3 页：展示关键结果

结果表不要只标粗最高值，还要说明：

- 多 seed 均值与方差；
- 效应是否稳定；
- 与随机选择和强 baseline 的差异；
- 结果是否超过测量噪声。

### 第 4 页：展示反例和失败样本

至少给出：

- 支持当前假设的样本；
- 不支持当前假设的样本；
- 无法判断的样本；
- 可能存在数据或评价问题的样本。

失败样本不是附录。它用于判断结论边界。

### 第 5 页：明确未排除解释

```text
当前仍可能的解释：
1. 重复证据更容易出现在靠前位置；
2. 重复改变了上下文长度分布；
3. 模型只是复制局部高频 token；
4. 结果依赖特定模型家族。
```

主动暴露未排除因素，比把结果包装得无懈可击更有研究价值。

### 第 6 页：请求具体决策

不要问：

```text
老师觉得我下一步应该做什么？
```

改成：

```text
我有两个下一步方案：
A. 先构造位置完全平衡的数据，验证频率效应；
B. 先扩展到三个模型，检查现象是否普遍。

当前证据下我倾向 A，因为位置偏置会直接威胁核心结论。
希望确认是否先完成因果区分，再扩展模型。
```

## 组会前检查

- 第一页是否有一句明确结论；
- 每张图是否支持一个具体判断；
- 是否展示了 bad case；
- 是否区分事实、解释和推测；
- 是否说明什么结果会推翻当前判断；
- 下周计划是否对应一个具体假设；
- 需要导师决策的问题是否足够具体。

## 组会后的记录

会议结束后立即记录：

```text
导师或同门提出的质疑：
这些质疑对应什么隐含假设：
决定执行的实验：
成功或失败标准：
优先级和截止时间：
与此前计划是否冲突：
```

不要只记录“导师建议多做几个实验”。必须把建议转化为可执行、可检查的决策。

## 不同进展状态如何汇报

### 有正结果

重点检查收益来源、方差、强 baseline 和反例，不要只讲最高分。

### 没有提升

说明实验原本验证什么、失败排除了什么，以及下一步是否仍值得继续。

### 代码还没跑通

报告已定位到哪一层、有哪些日志证据、排除了哪些原因，不要只说“环境有问题”。

### 本周主要在读论文

输出方法分类、争议、closest work 和待验证问题，而不是论文数量。

## 最终标准

一次有效组会结束后，应产生至少一个结果：

- 某个假设被保留、修正或放弃；
- 某个实验优先级被确认；
- 某个实现或评价风险被识别；
- 某个研究问题被进一步收窄。

如果组会结束后研究决策没有任何变化，它很可能只是进度播报。
