# 新人 30 天科研入门路线

目标不是 30 天内“想出顶会 idea”，而是建立一个最小科研闭环：能找到关键论文、复现可信 baseline、提出可验证问题、设计小实验并完成一次基于证据的汇报。

## 第 1 周：建立方向地图

### 任务

1. 向导师或同门确认课题组当前的 2–3 个核心问题。
2. 找到 1–3 篇综述、3–5 篇奠基工作、5–10 篇近两年工作。
3. 建立 Zotero collection 和文献矩阵。
4. 每篇论文只记录：问题、假设、方法、数据、指标、主要证据、局限。
5. 画出方法路线图，而不是按论文逐篇罗列。

### 本周产出

- 一页方向地图；
- 10–20 篇核心论文清单；
- 三条主要方法路线；
- 五个尚未解决或证据不足的问题。

### 不要做

- 收藏 200 篇但不分类；
- 每篇都从头精读；
- 把 AI 摘要当作自己读过；
- 还没理解任务就开始搭复杂工具链。

## 第 2 周：复现一个 baseline

### 任务

1. 选择代码、数据和评估脚本相对完整的 baseline。
2. 固定环境、数据版本、命令、随机种子和 commit hash。
3. 先跑最小数据或官方样例，再跑完整设置。
4. 对比论文数字与复现结果。
5. 记录差异，不要只记录最终成功结果。

### 本周产出

```text
复现目标：
官方结果：
复现结果：
环境与数据版本：
运行命令：
差异：
已排除原因：
仍待验证原因：
```

### 通过标准

不是“代码运行成功”，而是你能解释：

- 输入和输出是什么；
- 指标怎样计算；
- 结果受哪些参数影响；
- 为什么你的结果和论文相同或不同。

## 第 3 周：从现象到问题

### 任务

1. 分析 baseline 的错误样本。
2. 按可重复特征对失败分类。
3. 选择一个稳定现象，而不是一个偶然案例。
4. 阅读解释该现象的 closest prior work。
5. 写出至少两个竞争性解释。

### 本周产出

```text
现象：
发生条件：
失败样本数量与比例：
已有解释 A：
替代解释 B：
可以区分 A/B 的最小实验：
```

不要直接跳到“加模块”。没有明确现象和解释时，方法设计通常只是随机搜索。

## 第 4 周：完成一次最小验证

### 任务

1. 写出可证伪假设。
2. 推导假设成立时应观察到的结果。
3. 设计控制变量和对照组。
4. 运行最小规模实验。
5. 报告支持、削弱、否定或无法区分。
6. 用四页以内完成一次组会汇报。

### 组会结构

1. 研究问题；
2. 关键证据；
3. 当前判断与失败样本；
4. 需要导师决策的问题和下一步。

## 30 天完成检查

- [ ] 能解释方向中的主要任务、方法路线和评估方式。
- [ ] 能独立运行并检查一个 baseline。
- [ ] 有可追踪的实验记录和代码版本。
- [ ] 能从失败样本提炼稳定现象。
- [ ] 能写出可被否定的研究假设。
- [ ] 能设计一个区分不同解释的小实验。
- [ ] 能在组会上先给结论和证据，而不是汇报流水账。

## 推荐最小工具栈

| 任务 | 工具 |
| --- | --- |
| 文献检索 | Google Scholar、Semantic Scholar |
| 文献管理 | Zotero |
| 笔记与周报 | Markdown、Obsidian 或 Notion 二选一 |
| 代码版本 | Git |
| 实验记录 | Markdown/CSV，复杂后再用 W&B 或 MLflow |
| 写作 | 按课题组选择 Overleaf、Prism 或 Word |
| 汇报 | PowerPoint、Keynote 或 Marp |

工具只是执行层。30 天后最重要的不是安装了多少软件，而是能否完成一次问题—假设—实验—判断闭环。
