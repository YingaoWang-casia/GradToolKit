# AI 辅助科研：原则、边界与核验闭环

AI 的价值主要是降低检索、整理、检查和表达成本。它不能替代原文阅读、问题定义、实验设计、结果判断和学术责任。

本专题采用一个基本原则：

> AI 可以生成候选答案，但研究者必须建立证据链、执行验证并承担最终结论。

## 先判断任务属于哪一层

| 层级 | 典型任务 | AI 角色 | 研究者责任 |
| --- | --- | --- | --- |
| 机械辅助 | 格式转换、语法检查、表格整理 | 直接执行 | 检查格式和遗漏 |
| 结构辅助 | 文献字段抽取、组会大纲、实验日志整理 | 生成结构化初稿 | 对照原材料核验 |
| 批判辅助 | 寻找反例、审查 baseline、分析混杂变量 | 提供攻击点和候选解释 | 判断是否成立并设计验证 |
| 研究决策 | novelty、结果解释、是否投稿、是否止损 | 只能提供意见 | 必须由研究者决定 |

不要把第四层决策外包给模型。

## AI 辅助科研的最小闭环

```text
准备可信材料
→ 明确任务和禁止事项
→ 要求区分事实、推断和未知
→ 获得候选输出
→ 回到论文、代码、数据和日志核验
→ 记录修改与证据来源
→ 再决定是否采用
```

缺少“回到证据核验”这一步，就不是可靠的科研工作流。

## 推荐使用场景

| 场景 | 可以怎么用 | 必须核验什么 |
| --- | --- | --- |
| 论文初筛 | 抽取问题、方法、数据集和结论 | 摘要、方法、实验表格和限制 |
| 文献矩阵 | 将多篇论文整理为统一字段 | 每个字段是否能定位到原文 |
| Idea 审查 | 寻找 closest work、反例和隐含假设 | 检索是否充分、批评是否有证据 |
| 实验审计 | 检查 baseline、控制变量和缺失消融 | 代码、配置、日志和数据版本 |
| 代码辅助 | 解释报错、补测试、重构局部代码 | 实际运行、边界情况和性能变化 |
| 数据分析 | 提出图表和统计检验候选 | 数据类型、样本量、统计假设 |
| 写作润色 | 改善清晰度、语法和段落连接 | 是否改变结论、强度和限定条件 |
| 模拟审稿 | 从 novelty、实验和写作角度攻击论文 | 是否遗漏真正的 closest work |

## 禁止或高风险用法

- 直接生成并使用未核验引用。
- 让 AI 判断某个 idea “从未有人做过”。
- 用摘要替代方法、实验和附录阅读。
- 让模型生成不存在的数据、指标或实验结果。
- 让模型替你选择有利结果并隐藏负结果。
- 上传保密数据、未公开论文、内部代码、访问密钥或个人信息。
- 把语言润色后的夸大表述当成新的科学结论。
- 在没有运行代码的情况下声称问题已修复。

## 每次使用前写清楚四件事

```text
任务：希望 AI 完成什么？
材料：允许基于哪些内容？
边界：哪些内容禁止猜测或扩展？
验收：如何判断输出可靠？
```

示例：

```text
任务：检查这份实验设计是否能验证假设。
材料：研究问题、假设、数据说明和实验表格。
边界：不要假设未提供的模型能力，不要生成虚构引用。
验收：列出每个问题对应的证据、风险和最小补充实验。
```

## 输出必须区分三类信息

```text
已由材料支持
需要外部核验
模型的推测或建议
```

如果工具不能可靠标注来源位置，应降低它在文献和事实任务中的权重。

## 最终检查

在采用 AI 输出前，至少确认：

- 关键事实能定位到原文、数据、代码或日志。
- 引用真实存在，且确实支持当前表述。
- 数字、数据集名称、模型版本和指标口径没有变化。
- 推断没有被写成事实。
- 语言润色没有扩大结论范围。
- 代码已经运行，并有测试或最小验证记录。
- 没有泄露不应上传的材料。
- 最终判断由研究者作出，而不是因为模型表达得自信。
