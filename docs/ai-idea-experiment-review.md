# AI 批判 Idea 与实验设计

AI 更适合充当“反方审稿人”，而不是替你证明 idea 有创新。它可以暴露假设、缺失 baseline 和潜在混杂变量，但任何批评都需要回到文献和实验验证。

## 使用前必须提供

```text
研究问题
观察到的现象
现有解释
你的核心假设
最接近工作
计划中的实验
什么结果会反对你的假设
```

如果只提供一句“我想给模型加一个模块”，AI 只能围绕一个未经定义的方法想法生成表面意见。

## 第一轮：问题审查

要求 AI 检查：

- 研究对象和条件是否明确；
- 问题是否真实存在，而不是想象出来；
- 目标是否可测量；
- 问题、方法和指标是否混在一起；
- 成功后能增加什么知识；
- 失败后是否仍能获得结论。

合格输出应包含：

| 项目 | 输出 |
| --- | --- |
| 模糊概念 | 哪些词没有操作化定义 |
| 隐含假设 | 哪些前提未经验证 |
| 替代解释 | 同一现象还可能由什么造成 |
| 反例 | 在什么条件下问题不成立 |
| 最小验证 | 最低成本如何确认问题存在 |

## 第二轮：Novelty 攻击

让 AI 分别从以下角度攻击：

- 是否只是把 A 用到 B；
- 是否只是增加参数、数据或计算预算；
- 是否是已有模块的重新组合；
- 是否与 closest work 只有命名差异；
- 是否只有性能收益，没有机制证据；
- 是否只在一个有利数据集成立；
- 是否可以被更简单的方法替代；
- 是否只是修复实现问题而不是研究贡献。

不要接受“看起来新颖”或“有潜力”这种无证据评价。要求每个判断说明成立条件和需要检索的 prior work 类型。

## 第三轮：实验设计审计

要求逐项检查：

### 假设与预测

- 每个核心假设是否产生可观察预测；
- 预测是否与替代解释不同；
- 是否定义了反对假设的结果。

### Baseline

- 是否包含最接近工作；
- 是否包含简单但强的 baseline；
- 是否比较参数量、数据和预算；
- 是否给 baseline 同等调参机会。

### 控制变量

- 数据、预处理、模型规模、训练轮数和评价是否一致；
- 是否同时改变了多个关键因素；
- 是否可能存在数据泄漏或测试集调参。

### 消融与机制

- 每个模块是否对应一个明确假设；
- 消融能否区分模块必要性和交互作用；
- 是否只有“去掉模块性能下降”这一种弱证据；
- 是否有行为分析、分组实验或干预实验支持机制解释。

### 稳定性与成本

- 是否需要多个随机种子；
- 是否报告方差或置信区间；
- 收益是否超过随机波动；
- 是否报告时间、显存、吞吐或标注成本；
- 方法是否只在高预算条件下成立。

## 输出格式

推荐让 AI 输出审查表，而不是重新替你设计整篇论文：

```text
问题：
严重程度：致命 / 重要 / 次要
为什么是问题：
当前材料中的证据：
最小补充验证：
什么结果会消除该问题：
```

## AI 生成新实验时的限制

AI 可以生成候选实验，但你必须检查：

- 实验是否真的对应研究假设；
- 所需数据和标注是否存在；
- 指标是否能测量目标；
- 预算是否可承受；
- 是否与已有实验重复；
- 结果是否有明确解释空间。

不要因为实验列表很长就认为设计完整。优先保留能区分不同解释的最小实验。

## 模拟审稿

可以分别指定角色：

- novelty 审稿人；
- 实验严谨性审稿人；
- 统计与评估审稿人；
- 系统与成本审稿人；
- 可复现性审稿人；
- 领域专家。

每个角色都应基于同一份材料，独立给出：

```text
最可能拒稿的三个原因
缺失的关键证据
最危险的 closest work 类型
最低成本的补强实验
即使补实验也无法修复的问题
```

## 常见误用

- 让 AI 直接给 idea 打分，然后据此决定是否做。
- 没有提供 closest work，却让 AI 判断 novelty。
- 把 AI 提出的批评当成已证实事实。
- 每次得到负面评价后改提示词，直到模型赞同。
- 让 AI 生成大量实验，却不说明每个实验验证什么。
- 用模型的语言流畅度掩盖证据缺失。

## 最小提示词

```text
请作为严格审稿人，不要鼓励我。
基于我提供的研究问题、closest work、假设和实验计划，分别审查：
1. 问题是否成立；
2. novelty 是否只是组合或规模收益；
3. 实验能否证伪假设；
4. 缺失 baseline、控制变量和消融；
5. 可能的替代解释和 failure case。
每个问题给出严重程度、证据依据和最小验证方案。
材料不足时直接标注，不要补充虚构论文或结果。
```
