# 论文阅读笔记工作流

读论文最容易掉进两个坑：要么只看摘要和结论，要么每篇都精读到筋疲力尽。更稳的方式是分层阅读。

## 三层阅读法

| 层级 | 时间 | 目标 |
| --- | --- | --- |
| 快筛 | 5-10 分钟 | 判断要不要继续读 |
| 结构化阅读 | 30-60 分钟 | 抽取问题、方法、实验和局限 |
| 深读复现 | 半天到数天 | 理解公式、代码、实验细节和可复现性 |

## 快筛时只看这些

- Title：任务和方法是否相关
- Abstract：问题、方法、结果是否清楚
- Introduction 最后一段：贡献点是否具体
- Figure 1 或方法总图：是否能看懂主线
- Experiment：数据集和 baseline 是否与你相关
- Limitation：有没有你能继续做的空间

## 结构化笔记字段

复制 [论文阅读模板](../templates/paper-note-template.md)，每篇论文至少填：

```text
1. 论文解决什么问题
2. 为什么这个问题重要
3. 核心方法是什么
4. 用了什么数据集和指标
5. 主要结果是什么
6. 局限和失败样本是什么
7. 和我的课题有什么关系
```

## 论文标签建议

不要只打 `RAG`、`LLM` 这种大标签。建议用三层标签：

```text
任务标签：citation-faithfulness, turn-taking, retrieval-eval
方法标签：reranking, contrastive-learning, graph-based
状态标签：must-read, skimmed, reproduced, related-work, baseline
```

## 精读触发条件

只有满足下面任意条件，才值得精读：

- 它是你方向的奠基论文。
- 它是你 idea 的 closest prior work。
- 你的实验要复现它的 baseline。
- 你准备在 related work 里重点讨论它。
- 它的失败样本正好是你的切入点。

## 读完要能输出什么

```text
这篇论文把 X 问题建模为 Y；
它的核心贡献是 Z；
它在 A/B 数据集上证明了有效性；
但它依赖 C 假设，没有解决 D 场景；
如果我的课题要继续做，应该重点比较 E 和 F。
```

## 常见坑

- 只收藏 PDF，不写判断。
- 每篇都精读，导致一周只读两篇。
- 把作者自称的贡献当成真实贡献。
- 看不懂公式就完全放弃，忽略实验和问题定义。
- 让 AI 总结一遍就以为自己读过了。
