# 组会汇报准备

组会不是把一周流水账念一遍，而是让导师和同门快速判断：你在解决什么问题，证据是什么，下一步需要什么帮助。

## 组会前 30 分钟流程

1. 打开本周实验记录和论文笔记。
2. 写清楚本周最重要的 1-2 个问题。
3. 每个问题只放关键证据：表格、图、bad case、对比实验。
4. 标出你目前的判断：继续、暂停、换路线。
5. 准备 1 个需要导师决策的问题。
6. 复制 [组会周报模板](../templates/weekly-report-template.md)。

## 推荐结构

```text
1. 本周目标
2. 完成情况
3. 核心结果
4. 失败样本或异常
5. 当前判断
6. 需要讨论的问题
7. 下周计划
```

## PPT 页面分配

| 页码 | 内容 | 注意 |
| --- | --- | --- |
| 1 | 本周结论 | 先说结果，不从背景讲起 |
| 2 | 关键实验或阅读进展 | 只放和结论有关的证据 |
| 3 | bad case 或失败原因 | 展示你真的分析过 |
| 4 | 下一步计划 | 让导师能给建议 |

## 工具选择

- PowerPoint / Keynote：适合正式组会和导师习惯。
- Marp：适合 Markdown 写 slides，方便版本管理。
- Excalidraw：适合快速画方法草图。
- draw.io：适合规整流程图。
- Notion / Markdown：适合周报沉淀。

## 不要这样汇报

- “我这周看了很多论文”，但没有归纳。
- “实验效果不好”，但没有 bad case。
- “下周继续优化”，但没有具体假设。
- 一页塞满截图，没人知道要看哪里。
- 只展示成功结果，不讲失败原因。
