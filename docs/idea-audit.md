# Idea 与 Novelty 审计

Idea 不是方法名称，novelty 也不是“没人这样组合过”。审计目标是判断：这个想法是否提出了新的知识，还是只做了未经解释的组件替换。

## 先判断创新类型

| 类型 | 核心问题 |
| --- | --- |
| 新问题 | 是否定义了此前被忽略但重要的问题？ |
| 新现象 | 是否发现稳定、可重复且已有理论难以解释的行为？ |
| 新机制或解释 | 是否提出并验证了不同于已有工作的因果或机制解释？ |
| 新方法 | 是否有不可被简单替代的核心设计？ |
| 新评测 | 是否测量了现有指标遗漏的重要能力？ |
| 新数据 | 是否使此前无法研究的问题变得可研究？ |
| 新理论 | 是否给出新的边界、保证或统一解释？ |
| 负结果 | 是否系统否定了广泛接受但证据不足的结论？ |

方法创新只是其中一种，而且通常需要问题、机制或证据上的价值支撑。

## 十个强制问题

1. 问题是否真实存在？证据在哪里？
2. 谁会关心这个问题？
3. 最接近的三到五篇工作是什么？
4. 差异是机制差异，还是组件、模型或数据集差异？
5. 为什么现有方法不能自然解决？
6. 核心假设是否可以被否定？
7. 什么最小实验能验证关键判断？
8. 去掉新增复杂度后，贡献还剩什么？
9. 成功后社区获得了什么可迁移知识？
10. 失败后能否产生明确结论？

## 常见伪创新

```text
把 A 用到 B
加入一个注意力或门控模块
换更大的模型
更换 loss
串联两个公开模块
只在新数据集测试
只比弱 baseline
提升小于随机方差
参数、数据或算力增加但不说明
```

这些并非绝对不可发表，但默认创新性弱。必须证明新增设计改变了关键机制，而不是依靠更多资源或调参预算。

## 方法贡献审计

### 收益来源

- 是否使用更强 backbone？
- 是否增加参数量、训练数据、检索数据或人工标注？
- 是否使用更长训练、更大搜索空间或更多推理调用？
- baseline 是否获得同等调参预算？

### 必要性

- 去掉每个模块后会怎样？
- 简单替代方案能否获得相同收益？
- 方法是否只在一个数据集或模型上成立？
- 核心模块是否真的改变目标行为？

### 可信度

- 提升是否超过多随机种子的波动？
- 是否报告置信区间或显著性？
- 是否存在数据泄漏？
- 是否只挑选有利指标和数据子集？

## 红队评审

让同门或 AI 扮演严格审稿人，只攻击以下方面：

- 问题是否人为构造；
- closest work 是否遗漏；
- 差异是否只是工程组合；
- 实验能否支持机制结论；
- baseline 与预算是否公平；
- 指标是否真正对应目标；
- 是否存在更简单解释；
- 结论是否超出证据边界。

AI 可以生成攻击点，但“是否已有工作”和引用必须回到原论文与检索结果核验。

## 决策

- **继续**：问题真实、差异明确、最小验证成本可接受。
- **缩小**：问题有价值，但当前主张过大或变量过多。
- **重构**：现象成立，但原解释或方法不可信。
- **停止**：差异仅是组合、核心现象不稳定，或必须依赖不公平比较才能成立。
