# 如何定义一个值得研究的问题

研究主题、研究问题和方法 idea 不是同一件事。新人最常见的错误，是先想到一个模块，再反向包装问题。

## 四个层级

```text
领域：大语言模型
主题：RAG 事实一致性
问题：冲突证据下，哪些因素决定模型采纳哪条证据？
可验证问题：控制相关性、位置和长度后，证据频率是否仍影响回答？
```

只有最后两层能够直接指导实验。

## 一个合格问题的五项检查

### 1. 问题真实存在

需要证据，而不是直觉：

- 公开数据上的稳定现象；
- 真实系统日志；
- 多篇工作共同暴露的限制；
- 可复现的失败样本；
- 理论结论之间的矛盾。

### 2. 问题边界清楚

说明：

- 研究对象；
- 条件；
- 目标行为；
- 不研究什么；
- 结论预计适用于什么范围。

### 3. 已有方法不能自然解决

不能只说“效果仍有提升空间”。要说明：

- 现有方法依赖什么假设；
- 该假设在目标条件下为何失效；
- 现有实验为什么没有覆盖该问题；
- 最接近工作与你的问题差在哪里。

### 4. 可以形成可证伪假设

问题应允许多个解释，并能通过实验区分。

### 5. 成功或失败都有信息价值

好的研究不依赖必须涨点。即使假设失败，也能明确边界、否定常见解释或改进评估方法。

## 问题陈述模板

```text
在【条件】下，现有方法出现【稳定现象】。
已有研究通常将其解释为【解释 A】，并采用【现有方案】。
但【反例或证据】表明解释 A 可能不完整。
因此，本研究考察【具体变量】是否导致【目标现象】，并通过【区分性实验】与解释 B/C 比较。
```

## 从文献中找问题，而不是找句子

不要直接复制 limitation 或 future work。阅读时检查：

- 主张是否被实验真正支持；
- 指标是否测到了作者声称的能力；
- baseline 是否公平；
- 数据是否代表真实条件；
- 结论是否只在一个设置成立；
- 是否存在作者没有解释的异常结果。

## 常见伪问题

- “还没有人把 A 用到 B。”
- “模型效果还不够高。”
- “作者说未来可以加入某模块。”
- “这个新模型还没在该数据集测试。”
- “换一个 loss 可能有效。”

这些可以成为工程任务，但默认不是强研究问题。需要额外证明它们产生了新的现象、机制、评估或可迁移知识。

## 问题审查表

- [ ] 能用一句话描述现象，而不提自己的方法。
- [ ] 有数据或文献证据证明问题存在。
- [ ] 明确了条件、对象、目标和边界。
- [ ] 找到了 closest prior work。
- [ ] 说明了已有解释为何不足。
- [ ] 至少存在两个竞争性解释。
- [ ] 能设计实验区分这些解释。
- [ ] 即使假设失败，也会产生可报告结论。
