# 实验失败后的诊断与止损

失败实验不是“结果不好”，而是当前证据没有支持预期判断。正确动作不是立即继续调参，而是先判断失败发生在哪一层。

## 五类失败

| 类型 | 典型表现 | 优先动作 |
| --- | --- | --- |
| 实现失败 | 官方 baseline 无法复现、结果异常 | 检查代码、数据、环境和评估脚本 |
| 测量失败 | 指标与观察现象不一致 | 重新审查指标、标注和统计方法 |
| 数据失败 | 数据不包含假设需要的信号 | 分析覆盖范围，补充或更换数据 |
| 方法失败 | 方法没有产生预期行为 | 做机制消融和简单替代比较 |
| 假设失败 | 多轮可信证据持续反对核心预测 | 修改或放弃假设 |

## 诊断顺序

```text
结果异常
├── 输入、标签和评估是否正确？
├── baseline 是否可信复现？
├── 随机波动是否大于差异？
├── 数据是否覆盖目标现象？
├── 方法是否真正改变预期变量？
├── 是否存在更简单解释？
└── 核心假设是否错误？
```

不要从最后一层开始包装故事，也不要永远停在第一层说“可能没调好”。

## 实现检查

- 固定随机种子并保存完整配置；
- 在极小数据上手工检查输入和输出；
- 比较官方数据版本、预处理和评估脚本；
- 检查 checkpoint、tokenizer 和依赖版本；
- 保存 commit hash 和运行命令；
- 对关键模块写最小单元测试；
- 检查是否意外使用测试标签或未来信息。

## 测量检查

- 指标是否真正对应研究目标；
- 平均分是否掩盖关键子集；
- 是否只看单次运行；
- error bar 的定义是否明确；
- 人工评估是否有一致性检查；
- 评估模型是否存在位置、长度或风格偏置。

## 方法检查

问三个问题：

1. 新模块是否真的改变了假设中的中间机制？
2. 更简单的方法是否能获得相同结果？
3. 收益是否来自更多参数、数据、训练或推理调用？

只做最终指标消融不足以证明机制。

## 失败日志模板

```text
预期：
实际：
差异是否超过随机波动：
已检查实现：
已检查数据：
已检查指标：
可能解释：
区分解释的下一实验：
当前判断：实现 / 测量 / 数据 / 方法 / 假设 / 未知
```

## 何时继续

- 核心现象稳定存在；
- 失败原因可以通过一个低成本实验区分；
- closest work 没有直接解决；
- 新证据仍可能改变研究判断；
- 时间和算力成本与潜在价值匹配。

## 何时缩小问题

- 只在特定数据或模型上成立；
- 原主张过大，但局部现象稳定；
- 方法无普适收益，但揭示了有价值的边界；
- 机制无法证明，但评估或数据贡献仍可靠。

## 何时停止

- 连续多轮只改无理论依据的小参数；
- 核心现象无法稳定复现；
- 提升长期低于随机方差；
- 只有弱 baseline 或不公平预算下才有效；
- 每次失败都更换解释，却从不更新核心假设；
- 新模块越来越复杂，但没有机制证据；
- 最小验证已经否定核心预测；
- 继续投入的机会成本明显高于潜在价值。

停止一个 idea 不等于科研失败。及时终止无法成立的方向，是研究判断能力的一部分。
