# 实验设计：让结果能够区分不同解释

实验管理解决“能否复现”，实验设计解决“证据是否有效”。指标上涨不自动说明核心假设成立。

## 实验前先写决策表

```text
研究问题：
假设 H1：
竞争解释 H2/H3：
H1 成立时的预测：
什么结果会反对 H1：
自变量：
因变量：
控制变量：
最小区分实验：
```

如果无法写出反对假设的结果，实验通常只是确认偏误。

## 变量与对照

- **自变量**：研究者主动改变的因素。
- **因变量**：用于观察影响的结果。
- **控制变量**：避免同时变化的因素。
- **对照组**：没有目标机制或采用标准方案的设置。
- **混杂因素**：同时影响自变量和结果的其他因素。

例如比较新检索策略时，应控制生成模型、上下文长度、候选文档数、训练数据和推理预算，否则无法确定收益来源。

## Baseline 选择

至少考虑：

1. 任务领域的标准 baseline；
2. 最接近工作的原始实现；
3. 简单但强的 heuristic；
4. 与新方法资源预算匹配的 baseline；
5. 必要时加入 lower bound、upper bound 或 oracle。

不能只选择容易被击败的方法。

## 公平比较

检查：

- backbone 是否相同；
- 参数量是否相近；
- 训练数据是否一致；
- 调参预算是否一致；
- 训练和推理成本是否报告；
- 是否使用了额外标注或外部知识；
- 测试集是否参与开发。

## 随机性与统计

- 多个随机种子；
- 报告均值与离散程度；
- 说明 error bar 的含义；
- 对小幅提升检查是否超过方差；
- 避免只挑选最好一次运行；
- 数据量较小时说明统计方法的假设。

## 消融实验

消融不是机械地逐个删模块，而是回答机制问题：

- 哪个组件贡献主要收益？
- 组件之间是否存在交互？
- 简单替代是否同样有效？
- 性能收益是否来自参数量或额外计算？
- 核心机制是否改变预期行为？

## 鲁棒性与边界

至少检查一部分：

- 不同数据集或数据分布；
- 不同模型规模；
- 噪声、缺失或对抗条件；
- 超参数敏感性；
- 性能—成本权衡；
- 失败样本类别；
- 结论不成立的条件。

## 数据泄漏检查

- 训练、验证和测试是否重复；
- 数据预处理是否使用测试统计；
- LLM 或检索库是否可能见过测试答案；
- 人工筛选是否看过标签；
- prompt、规则或阈值是否在测试集上调整。

## 实验结果解释

| 结果 | 合理判断 |
| --- | --- |
| 符合预测，替代解释被控制 | 支持假设，但不是绝对证明 |
| 只在部分条件成立 | 缩小结论边界 |
| 与预测相反 | 削弱或否定假设 |
| 多个解释都能导致结果 | 无法区分，需要新实验 |
| 提升低于随机波动 | 不能声称有效 |
| 依赖更多参数、数据或调用 | 报告资源贡献，不能全归因于机制 |

## 实验完成检查

- [ ] 实验对应明确的研究问题。
- [ ] 写出了竞争解释和反证条件。
- [ ] baseline 足够强且比较公平。
- [ ] 控制了关键混杂因素。
- [ ] 报告随机性、成本和失败样本。
- [ ] 消融对应机制，而非凑表格。
- [ ] 结论没有超出实验覆盖范围。
