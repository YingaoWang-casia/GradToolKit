# 两周建立研究方向地图

这篇内容适合刚进入新方向、导师只给了一个宽泛关键词、或读了很多论文仍不知道领域结构的人。

目标不是收藏尽可能多的论文，而是在两周内形成一张可以支持研究决策的方向地图。

## 最终产出

两周结束时至少应得到：

- 一页问题定义；
- 一张方法路线图；
- 一份 20 到 40 篇的核心文献表；
- 一张数据集与指标对照表；
- 5 篇 closest prior work；
- 3 个尚未解决的问题；
- 1 个可以在一周内验证的最小问题。

如果只有几十篇 PDF，没有上述产出，说明调研尚未完成。

## 第一步：把方向拆成四类问题

以“RAG 评估”为例，不要直接搜索一个大词。先拆成：

```text
任务：系统到底要完成什么？
对象：评估检索、生成、引用还是端到端系统？
条件：长文档、冲突证据、跨语言还是实时更新？
目标：准确性、忠实性、鲁棒性、成本还是可解释性？
```

组合后才能形成更有信息量的检索式，例如：

```text
conflicting evidence + retrieval augmented generation + faithfulness evaluation
```

## 第二步：选择种子论文

第一轮只保留：

- 1 到 2 篇综述；
- 3 到 5 篇奠基工作；
- 5 到 10 篇近两年代表性工作；
- 5 篇与你当前问题最接近的工作；
- 2 到 5 篇负结果、局限或失败分析。

高引用不等于最相关。种子论文的作用是帮助你建立引用网络和术语表。

## 第三步：建立文献矩阵

每篇论文只记录能够支持判断的字段：

| 字段 | 要回答的问题 |
| --- | --- |
| 问题 | 它具体研究什么现象？ |
| 假设 | 作者认为为什么会发生？ |
| 方法 | 核心机制是什么？ |
| 数据 | 数据是否真正覆盖该问题？ |
| 指标 | 指标是否测量目标能力？ |
| Baseline | 比较是否公平且充分？ |
| 结论 | 哪些结果直接支持主张？ |
| 局限 | 在什么条件下不成立？ |
| 关系 | 与你的问题有什么直接关系？ |

不要把摘要原文复制进矩阵。矩阵记录的是你的判断，不是论文转述。

## 第四步：按不同轴重新分组

至少做四次分组：

1. 按问题类型分组；
2. 按方法机制分组；
3. 按数据与评估设置分组；
4. 按核心假设分组。

如果一种分类方式无法解释论文间差异，就换一个轴。不要为了得到整齐的 taxonomy 强行分类。

## 第五步：找 closest prior work

最接近工作不是标题最像，而是同时接近：

- 问题定义；
- 输入输出；
- 方法机制；
- 数据条件；
- 评价目标。

对每篇 closest work 写一段对照：

```text
它解决：
它假设：
它证明：
它没有覆盖：
我的问题与它的实质差异：
```

如果差异只能写成“我用了另一个模型或模块”，创新性通常不足。

## 第六步：从 gap 转向可验证问题

弱 gap：

```text
还没有人把方法 A 用在数据集 B。
```

更强的问题：

```text
现有方法在冲突证据下持续失败；
已有工作将失败归因于检索噪声，
但在控制相关性后现象仍然存在；
因此需要验证证据频率是否造成独立偏置。
```

问题必须包含现象、已有解释、矛盾以及可验证对象。

## 两周安排

### 第 1 到 3 天

建立术语表、找到种子论文、理解任务定义。

### 第 4 到 7 天

完成 20 到 30 篇快筛，形成初版方法路线和文献矩阵。

### 第 8 到 10 天

精读 closest work，核对数据、指标、baseline 和局限。

### 第 11 到 12 天

整理未解决问题，排除纯组件组合和仅换数据集的伪 gap。

### 第 13 到 14 天

选择一个最小问题，写出假设、预测、实验和否定条件。

## 完成检查

你应当能够在五分钟内解释：

- 这个方向研究的核心问题；
- 主要方法为何分成这些路线；
- 当前最强证据支持什么结论；
- 社区默认了哪些尚未验证的假设；
- 哪个最小实验可以减少一个关键不确定性。
